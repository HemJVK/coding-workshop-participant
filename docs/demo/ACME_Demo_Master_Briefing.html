ACME Performance Platform - Demo Master Briefing

Prepared for: Workshop demo and architecture review panel
Date: April 17, 2026
Project: coding-workshop-participant
Focus: End-to-end architecture, edge cases, and technical specifications
Executive Positioning: This platform unifies HR operations and people analytics under one secure API surface. It delivers measurable business insights (attrition risk, high potentials, skill gaps) while maintaining clear role-based controls and service boundaries.

1. Business Value Story

  • Centralizes employee performance, competency, goals, development, and training data into one navigable system.
  • Answers strategic workforce questions via dedicated analytics endpoints, not just raw CRUD records.
  • Supports role-aware operating model: Admin, Manager, HR, Employee.
  • Provides production-shaped deployment path for both local and AWS serverless modes.

2. System Architecture Overview

2.1 Entry and Routing

  • Frontend (React + Vite + MUI) sends requests through Axios to /api/*.
  • FastAPI gateway (backend/main.py) is the unified backend ingress.
  • Gateway dynamically loads and dispatches each backend service module at runtime.
  • Cloud path uses CloudFront + Lambda Function URL + IAM authorization.

2.2 Backend Service Domains

Service Purpose Core Endpoints Role Controls
auth-service Authentication, registration, user profile, user admin /login, /register, /me, /users Admin-only user administration
employees-service Employee master records GET/POST/PUT/DELETE employees Manager scope by managed employees; admin delete
reviews-service Performance reviews and ratings GET/POST/PUT/DELETE reviews Manager scope checks + admin delete
goals-service Goal tracking + progress endpoint CRUD goals, /id/progress Manager scope checks, role-based delete
competencies-service Competency catalog + employee assessments CRUD competencies, /employee/{id} Role checks for create/update/delete
training-service Training records lifecycle GET/POST/PUT/DELETE records Manager employee-scope enforcement
development-service Development plans GET/POST/PUT/DELETE plans Role + manager scope checks
analytics-service Workforce intelligence aggregation /skill-gaps, /high-potentials, /attrition-risks, /distribution/skills User required; manager-scoped data filters

3. Security and Identity

3.1 Authentication

  • JWT issued by auth-service with 8-hour expiry and role claims.
  • Frontend stores session token and user metadata in browser local storage.
  • Axios request interceptor injects bearer token automatically.
  • Response interceptor performs global 401 handling and forced logout redirect.

3.2 Authorization

  • UI route-level guard for authenticated and role-specific pages (for example admin page).
  • Backend service-level checks enforce true authorization regardless of UI state.
  • Manager-specific access patterns enforce ownership scope by manager_id.

3.3 Infrastructure Edge Security

  • CloudFront sets workshop token header for gateway admission checks.
  • Lambda Function URL is IAM protected.
  • CloudFront origin request policy forwards viewer headers except host for API compatibility.

4. Data and Persistence Design

  • PostgreSQL is the persistence backbone across services.
  • Each service defines own schema bootstrap with CREATE TABLE IF NOT EXISTS.
  • Cold start/startup performs database initialization with seed records for demo readiness.
  • Connection strategy relies on module-level reusable connection object for warm invocation efficiency.

5. Frontend UX Architecture

  • React Router protected route model with dedicated auth guard.
  • Dashboard aggregates analytics and employee status concurrently using Promise.all.
  • KPI cards and tables expose operational and strategic metrics side-by-side.
  • Employee detail page composes reviews, competencies, training, goals, and plans into one profile pane.

8. Edge Cases and Technical Risks (Precise)

Area Risk Impact Recommended Mitigation
Gateway path translation Gateway forwards stripped path (for example /123) while many services parse IDs expecting at least 2 path parts. High for read-by-id/update/delete correctness. Normalize forwarded path to include service segment or relax service parser to accept single-segment IDs.
Secrets defaults Default JWT secret/password values in code and compose. High in real deployment if unchanged. Use environment-managed secrets (AWS Secrets Manager/SSM) and fail fast when missing.
Service map startup health entry exists in map but has null target; startup still iterates map. Medium noisy startup logs. Skip non-service sentinel keys during initialization loop.
Test breadth Automated tests currently focus on auth, employees, analytics. Medium compared to broad coverage goals. Add tests for reviews, goals, competencies, training, development and gateway path edge behavior.
Delete semantics Mixed hard-delete and soft-delete patterns across services. Medium inconsistency for auditing/data retention. Define platform-wide data lifecycle policy and align implementations.

11. Panel Q and A - Strong Answers

Q: Why one gateway instead of separate API endpoints?

A: It simplifies external ingress, security policy, and client integration while preserving service-domain boundaries internally.

Q: How is authorization enforced beyond the UI?

A: Backend handlers use token-derived user context and explicit role checks in each service function. UI guards only improve UX, not security boundary.

Q: What is your biggest technical risk and fix plan?

A: Path-to-ID parsing mismatch risk in gateway/service boundary. Planned fix is deterministic path contract normalization and regression tests for all entity ID routes.

Q: What makes this more than a CRUD app?

A: Analytics service provides targeted workforce intelligence from correlated datasets: low performers (attrition risk), high-potential talent, and competency gaps by category.

12. Conclusion

This project demonstrates a practical, deployable, and business-oriented microservice architecture with strong foundations in auth/RBAC, modular domain services, and decision-grade analytics. The immediate improvement path is clear and tractable: tighten gateway path contracts, harden secret management, and broaden automated test coverage.
